# 引用与来源核验

结果引用包含 collection/document/chunk ID、文档版本、SHA256、索引版本、
库内相对路径、行号/页码/段落、实际摘录及核验状态。
模型不能通过返回一个文件路径或 ID 获得文件访问权。

模型使用 `[K:chunk_id]` 标记已提供证据。流式过滤器可以处理被网络分段的标记，
丢弃未知或不完整引用，不把模型编造的标记变成可点击来源。
界面将真实标记显示为「来源」按钮，展开当前消息对应的来源；代码块不改写。
来源面板标为「检索时来源已核验」，并说明不代表答案的每个结论都通过事实核查。
语音过滤器不朗读内部引用 ID。

「在文件夹中定位」会再次经后台核对会话、角色、grant、版本、哈希、根目录及实际文件。
主进程只接受核验后的路径并使用系统的文件夹定位，不启动源代码、宏或文件关联程序。
失效来源不能打开；软件保留一个明确的过期/撤销提示，不把旧摘录当成当前事实。

模型地址或名称变化、目录移除、知识库删除、源文件修改/删除、索引版本变化时重新核验。
来源撤销或目标模型变化后，旧的知识回答不会偷偷进入后续历史/引用回复上下文。
用户仍可在自己的聊天记录中阅读既有答案；授权不等于删除历史。

Checkpoint 只存引用身份、版本和摘要，不存原文。恢复时重新检查授权、模型目标授权及源文件。
Workflows 根据不可变图中的实际知识祖先追踪来源，Transform 不能清除这个约束。
RAG 不是模型事实正确性的形式证明；没有语义支撑的自然语言结论仍可能出现，需要人工复核。
