# Agent Recovery 与安全续接

本地审核版本 `0.2.0-recovery.1`。使用既有 AgentService、RuntimeRegistry、
AgentTaskRuntime、权限、Trace、Evaluation 和 SQLite，不建立第二套 Agent。
公开下载 v0.1.2 不包含本分支的新功能。

## 使用

1. 在独立档案中打开工作模式，正常提交任务和处理授权。
2. 工作流模块底部的「任务恢复与检查点」显示当前会话的最近 30 个任务。
3. 对已中断或未完成任务选择「恢复预览」。预览只重新读取状态，不执行待续接工具。
4. `SKIP_VERIFIED` 表示当前证据支持复用；`EXECUTE` 表示仍需执行；`REVIEW` 表示停止自动续接。
5. 需要执行有副作用的剩余步骤时，逐项确认本次权限，再点「安全续接」。执行前再次核验。
6. 可以暂停、继续当前执行、手动接管或取消。终态任务不能再次续接。
7. 「检查检查点」显示实际工具、意图摘要及结果证据；「执行追踪与只读回放」沿用原 TraceViewer。

![实际安装版重启后的恢复预览和检查点](screenshots/recovery.png)

安全续接保存回复到原会话，通过原 SSE 更新界面；不追加模型或语音请求。
逻辑任务 UUID 保持不变，每次续接建立新的执行 UUID 和 Trace，旧 Trace 不被改写。
用户点击「创建新计划」属于另一个操作：需要单独同意可能计费的模型规划，且不自动执行。
已执行过非只读步骤的任务不提供从头重放。

## 哪些情况可恢复

|情况|当前策略|
|---|---|
|只读文件/状态请求发生可重试超时|重新检查权限，有限次数重试|
|窗口仍存在但焦点验证失败|读取当前应用窗口证据，有限次数重新聚焦|
|GitHub / 百度 / 哔哩哔哩的固定搜索页 DOM 变化|验证当前主机与 DOM，再通过已有固定 GET 搜索操作重新取得结果|
|文件写入完成但进程在记录结果前退出|当前哈希匹配预期时跳过重复写入|
|文件被修改、工作区变化、检查点损坏|拒绝自动续接，不覆盖文件|
|应用已退出、锁屏、用户干预|停止自动操作，等待用户检查|
|脚本、表单、安装/删除等操作是否完成不明|不自动重放|
|模型超时/不可用|不重复计费请求，不切换供应商|

## 边界

- 这是保守的、确定性的局部恢复；不保证任意应用、网页、脚本都能断点续接。
- 初始执行开始后总年龄最多 30 分钟；跨重启仍计入。过期记录可查看，但不再续接。
- 每步最多 2 次额外重试；任务的恢复尝试（包括续接）总计最多 4 次，人工续接另受 4 次上限约束，累计步骤预算 12。
- 当前模型重规划和费用预算为 0。没有未授权的模型回退、无限循环或静默提高权限。
- 重启只标记中断并展示候选，不自动重开应用、浏览器或脚本，不恢复鼠标焦点。
- 已提交的通用列表/搜索结果不能完全重新核验时，也会转人工检查。
- 原计划没有可选步骤标记，因此没有“跳过必需步骤”按钮。
- 本地租约与哈希校验不构成外部系统 Exactly Once；外部状态可以在观察后再次变化。
- 整个 Windows 桌面不是权限沙箱；已提交给线程/外部应用的动作不能保证随协程取消回滚。
