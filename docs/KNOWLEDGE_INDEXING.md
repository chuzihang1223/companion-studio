# 解析、分块与增量索引

支持 Markdown/TXT、Python/TS/TSX/JS/JSX、JSON/YAML/YML、PDF 和 DOCX。
UTF-8/BOM、带 BOM 的 UTF-16 与严格 GB18030 解码；二进制和无效编码明确失败。
PDF 只取文本层，不做 OCR；加密、损坏、无文本层或超过 400 页均给固定错误码。
DOCX 只解析文档 XML 的段落，不执行宏、外链、DTD 或实体。

PDF/DOCX 在自有子进程中解析：15 秒截止、Windows Job 512 MiB 内存限制、
仅继承必要系统变量、不继承密钥。取消会结束本次拥有的解析进程。
文本提取上限 500,000 字符，DOCX XML 上限 8 MiB；不静默截断并声称完整索引。

Markdown 记录标题/段落与行号；Python 顶层函数/类使用 AST，语法未完成时降为行文本；
TS/JS 使用保守声明边界；TXT 使用段落；PDF 保留实际页码；DOCX 保留段落序号。
默认片段 1,000 字符、100 字符重叠，可配置 200–2,000 字符；每文档最多 256 片段。
片段 ID 来自文档身份、内容摘要和位置，未变内容不会随机换 ID。

每次读取检查 lexical scope、符号链接/Windows reparse point、根目录身份、实际打开的句柄路径、
读前/读后状态和 SHA256。解析后、提交前再次读取核验；发生变化不写入过期证据。
长路径或文件权限问题返回受控错误，不读取替代路径。

增量结果：NEW、MODIFIED、UNCHANGED、DELETED、ERROR。每文档一次原子替换片段、FTS 和旧向量，
成功扫描结束才统一确认删除文件。失败文档立即失效旧片段；查找与引用时还会重新核验源文件。
重建索引会重新解析全部授权文档，但不修改源文件。

IndexJob 持久保存 PENDING、SCANNING、PARSING、CHUNKING、INDEXING、PAUSED、COMPLETED、
FAILED、CANCELLED、NEEDS_REVIEW，记录逐文档计数与固定错误码。最多两个自有任务，
同一个库只能一个任务；单次扫描最多检查 100,000 个目录项，所有数量和字节限制均有上限。
数据库不在解析期间持锁。

关闭/崩溃后未完成任务标为 NEEDS_REVIEW，不伪造完成，也不自动重放。
用户重新索引时重新扫描授权目录，复用已提交且哈希未变的文档，舍弃半读进度。
索引未完成/取消/待复核的整个库默认不可供证据回答，完整扫描完成后重新就绪。
可选 Embedding 失败保留已成功的关键词索引，混合搜索明确回退。

索引任务历史每库最多保留 30 条；文档元数据最多为当前文档上限的两倍，避免长期重命名/删除导致无限增长。达到元数据上限后要求明确重建索引；重建先清除该库索引，再扫描源文件，取消时不会伪装成仍可用的旧索引。
