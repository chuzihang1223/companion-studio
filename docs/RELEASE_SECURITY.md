# 发布安全检查范围

公开发布前使用 `scripts/audit-release.py` 检查公开源码、可达 Git 历史及新生成的 Windows 目录版。它不会扫描用户电脑的私人目录，不发送文件到外部服务，不执行打包应用代码，也不修改 Git 仓库。

检查成功只表示已定义的规则与文件完整性通过，不代表没有任何凭据、隐私或软件漏洞。安装包运行、Windows GUI、第三方资源权利及最终公开授权仍是独立门禁。

## 1. 本地使用

在公开项目根目录、已安装开发依赖的环境中执行：

```powershell
.\.venv\Scripts\python.exe -B scripts/audit-release.py --source . --report .cache/release-source-audit.json
```

完整发布检查还应指定实际生成的 `delivery` 或 `win-unpacked` 目录。例如：

```powershell
.\.venv\Scripts\python.exe -B scripts/audit-release.py --source . --delivery build/studio-0.1.1-example/delivery --report .cache/release-audit.json
```

示例路径需要替换成当前构建输出，脚本不会自动选中用户已安装软件或私人资料。目录版审计需要已安装 `desktop/node_modules/@electron/asar`、Node.js、构建用 PyInstaller，以及与冻结后端兼容的 Python 版本。

源代码 ZIP 没有 Git 历史时，可以使用 `--no-history` 明确只检查源码。正式 CI / Release 必须保留历史检查，不使用这个开关。公开仓库与源代码压缩包的检查范围不同，应保留报告里的 `scope` 字段。

退出码为 `0` 表示所启用范围没有发现问题，`1` 表示发现问题或有启用范围无法读取。报告可写入 `--report`，同时在标准输出打印 JSON。不要把本地构建目录、用户资料或包含原始异常文本的调试日志当成公开报告上传。

## 2. 当前源码

复用 `scripts/export-public.py` 的导出文件集合、资源白名单、密钥表达式和开发者路径表达式，再检查显式凭据赋值。

- 检查已知 API Key、GitHub Token、私钥头部、AWS 和 Slack Token 模式。
- 检查较长的显式 `api_key`、`password`、`access_token` 等赋值；没有可识别模式的短密码或间接拼接密钥仍可能漏检。
- 检查 Windows 用户目录与开发者桌面绝对路径，不拒绝正常的 Windows 系统路径、测试目录和相对项目路径。
- 拒绝真实 `.env`、用户配置、数据库、日志、语音、模型和非白名单图片进入公开导出范围。
- 仅在 `tests/` 与 `backend/tests/` 路径豁免明确且重复零 / x 的测试占位 Token，以及已核实的固定值 `isolated-test-key`；其他测试文件里的真实格式仍检查。

第三方许可 / 上游源码中的上游开发者路径不按本项目个人路径处理，但这些文件仍检查凭据模式，并必须通过许可清单校验。历史来源与授权不能靠文件名自行证明。

## 3. Git 历史

脚本只使用 `rev-parse`、`rev-list`、`ls-tree` 与 `cat-file` 读取命令：

1. 确认目标为当前仓库根目录，避免误扫外层目录的 Git 项目。
2. 枚举本地全部 refs 及 HEAD 可达提交。
3. 遍历每个提交的完整树，收集所有历史文件名及唯一 blob。
4. 扫描 UTF-8 文本，包括曾提交后删除的文件，以及其他分支仍可达的旧内容。
5. 检查历史私密文件类型、链接 / 子模块，以及开发者路径和凭据模式。

二进制历史 blob 会统计，但不会伪装成已完成图片内容识别或二进制反编译。不可达对象、仅存在于 reflog 的对象和远程未获取 refs 不在检查范围。CI 必须采用完整获取历史的 checkout；“本地全部 refs”不等同互联网上全部历史副本。

单个 blob 读取上限是 64 MiB，超过上限会阻断审计。浅克隆只能检查当前可达的有限历史，因此发布工作流应使用 `fetch-depth: 0` 并获取需要审计的远程分支 / 标签。

## 4. Windows 目录版

### 文件与公开资源

遍历目录版真实文件，不沿 symlink 或 Windows junction 读取外部内容。检查 `UserData`、私人归档、日志和配置，以及数据库、音频、模型等禁止发布内容。图片和原创 SVG 根据公开源码白名单的 SHA256 内容确认，冻结后端的默认角色必须与公开 `characters/assistant.json` 一致。

Electron 的官方运行文件与当前固定版本 `node_modules/electron/dist` 的文件逐项哈希对照。官方 `icudtl.bin`、V8 快照等二进制不能因为 `.bin` 扩展名被误判为私人模型。后端所需 DLL / PYD 不会被当成用户资料，但此检查不包含恶意代码分析、数字签名认证或所有原生库的独立来源证明。

### Electron ASAR

通过已安装的 `@electron/asar` 读取成员清单、元数据及文件内容，不调用其中的 JavaScript。Windows 路径分隔符会规范化，链接、异常路径和超大成员会阻断检查。

扫描自有脚本的文本凭据和个人路径，检查禁止文件类型与非白名单图片。`unpacked` 成员由物理目录遍历覆盖；第三方 `node_modules` 仍检查凭据模式，个人路径与图片分类保留 vendor 边界。

### 冻结 Python

使用 PyInstaller 的 CArchive / PYZ Reader 读取入口 `run` 及 `app.*` 模块的代码对象，递归检查编译文件名、字符串 / 字节常量、嵌套函数和常量容器。代码对象只读取，不导入或执行。

此范围不包含所有第三方 Python 模块、动态构造值、原生 DLL 或所有字节码数据流。读取需要与构建兼容的 Python；版本不兼容、缺少入口 / 应用模块或归档损坏会返回检查错误，不能标记通过。随包的后端源码也接受文本检查。

目录版通过不代表 NSIS Setup 的实际安装、卸载和 Windows 界面操作通过；应另行保存安装与 GUI 验收记录。

## 5. 第三方文件完整性

`licenses/source-manifest.json` 记录许可与 corresponding source 文件路径、大小和 SHA256。脚本逐项确认：

- 清单路径在 `licenses/` 内，拒绝绝对路径、盘符和父级跳转。
- 清单文件实际存在，且大小与哈希完全匹配。
- 不存在清单之外的新许可目录文件，清单文件本身除外。
- 目录版的许可清单与公开源码清单一致。

FFmpeg 源码归档、Chromium 许可和相关上游构建定义按已有规则保留。完整性检查能够发现缺失或修改，不能替代上游许可证、再分发条件和授权的人工判断。

## 6. 报告脱敏与失败行为

每项发现只输出 `scope`、相对文件定位、规则名，历史发现可带 blob 编号。报告没有匹配片段、Token 值、原始文件正文或子进程 stderr。文件定位本身包含私人路径时，用摘要代替。

任何启用范围出现读取 / 解析异常，报告记录异常类型和固定说明位置，不回显可能带敏感内容的异常消息。CI 应上传该脱敏 JSON，不上传扫描期间的原始内容。

报告仍可能出现仓库公开文件名或模块名；它不是任意输入内容的匿名化服务。发布前应检查报告及其他构建资产的实际内容。

## 7. 回归覆盖

`tests/test_release_audit.py` 使用合成数据验证：

- 明确测试占位与真实格式的区分。
- 显式凭据赋值与报告路径脱敏。
- 多 refs 历史中已删除内容仍会被发现，合法图标不误报。
- 许可文件缺失、修改和额外文件。
- 上游路径边界与仍需检查的凭据模式。
- 真实 ASAR 读取和非白名单图片。
- 冻结代码常量递归读取不会执行模块正文。
- 目录版禁止资源和 CLI 非零退出。

回归中的 Git 写入仅发生在测试新建的隔离目录。真实维护仓库只读；测试不会使用开发者的账号密钥或运行第三方模型请求。
