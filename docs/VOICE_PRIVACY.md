# 语音权限、资源和数据

- 启动、打开语音面板和开启会话都不采集；用户点击录音才请求音频轨道。
- 只允许可见主窗口的同源 audio 权限。摄像头、混合音视频、子页面和嵌入网页拒绝。
- 隐藏或关闭窗口撤销本次主进程许可；定时任务不能重新授予。
- 原音只在当前轮次 RAM 中，结束识别、失败或取消后清空，不写原音文件、不上传。
- 终句需要校对发送才进入原聊天和当前配置的模型；这一步的文本按照原聊天持久化。
- 云端 TTS 的回复文字另需独立允许；配置和密钥始终留在后端，helper 不继承服务密钥。

输入协议固定为单声道 PCM16 LE，100ms 常用帧，10–200ms 验证范围；
只接受 16k / 24k / 44.1k / 48k，并实际转到 16k。RIFF/Ogg 容器、混合采样率、
错序、NaN、长度不符及超过 30 秒的输入拒绝。VAD 噪声候选没有执行权限。
前端最多 8 帧待传，语义队列 16、事件队列 32；播放器超过约 8 秒积压会背压，
持续超过 30 秒拒绝继续。每轮 TTS 收集上限 16MB。

原朗读过滤器新增跨 token 的凭据前缀过滤，并保留代码围栏、行内代码、JSON 和 URL 状态，
避免语义长度切分朗读凭据尾部。工具输出不会直接接入 TTS。过滤只覆盖定义的格式，
不能证明任意私人句子都已脱敏；不要把秘密发给模型。
Trace 仅持久化已允许的 UUID、状态、计数和用时，不存录音、转写原文、API 密钥或参考音频。
回放只读取原 Trace，不调用麦克风、TTS 或工具，也不重新执行副作用。

生成的回复 WAV 位于当前独立档案的 `voice_cache/realtime`，按数据库归属清理，
128MiB / 7 天；未知及孤立文件计入配额，但不会擅自删除。只清理本命名空间的受管文件，
不清理原语音缓存、角色、模型、个人版或其他用户目录。空间不足会报告缓存未保存，
不会要求重新执行已经完成的 Agent 任务。目录和 helper 临时目录拒绝越界及链接。
临时编译目录由每次 helper 独占；清理只在自己的进程和 Job 结束后执行。

Windows 音频沙箱需要公开运行文件的只读/执行权限。安装器已有固定白名单准备脚本，
不能以关闭音频沙箱、给用户档案继承读取权限或授予任意目录写权限作为修复办法。
应用崩溃后语音输入不会自动恢复；工具恢复仍通过原 Recovery 确认未知外部副作用。
