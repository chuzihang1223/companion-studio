# 工作台维护说明

本文说明当前工作台的实现约束，供维护布局、会话和流式展示时参考。工作台仍使用现有 React 组件和浏览器事件；这些说明不是新的功能承诺。

## 1. 模块和职责

| 模块 | 职责 |
| --- | --- |
| `WorkspaceModuleRegistry.ts` | 定义模块 ID、标题、可关闭能力和最小尺寸。当前每种模块只有一个实例。 |
| `Workbench.tsx` | 组合工作台、任务状态、停靠栏和工具输出，选择当前会话的布局。 |
| `WorkbenchLayout.ts` | 加载布局、撤销历史和默认模板，提交已完成的布局变更。 |
| `WorkspaceGrid.tsx` | 将布局转换为可见坐标，管理一次指针缩放并绘制几何结果。 |
| `WorkspaceLayoutEngine.ts` | 默认模板、旧布局迁移、坐标转换、开启和放置模块。 |
| `WorkspaceSplitLayoutEngine.ts` | 识别共享边界，计算相邻模块随同一分割线的尺寸变化。 |
| `LayoutCollisionResolver.ts` | 寻找空闲位置，修复重叠；固定位置模块作为障碍物。 |
| `useModuleDrag.ts` | 停靠栏模块的拖拽手势、落点及点击抑制。 |
| `ResizeSessionController.ts` | 每次缩放手势的唯一动画帧调度、指针位置和清理。 |
| `WorkspaceAutoScrollEngine.ts` | 缓存视口测量，计算缩放时的边缘滚动速度和允许滚动范围。 |
| `WorkspaceBrowser.tsx` | 协调内嵌网页的位置、裁剪和缩放期间的隐藏。 |

`WorkspaceResizeAutoScrollController.ts` 目前是兼容导出，实际调度由 `ResizeSessionController` 承担。

## 2. 布局与坐标空间

持久布局使用版本 `3`，以 `canvasWidth` 为横向基准，模块拥有 `x/y/width/height`。它保留旧网格字段用于兼容，但当前主要使用自由矩形布局。共享分割线采用版本 `1`、类型 `shared-boundaries`，可以表达 T 形连接。

渲染前，`effectiveLayout()` 把横向位置和宽度映射到实际容器宽度。纵向位置、高度通常不缩放；窄视口会使用纵向排列。用户提交变化时，`canonicalLayout()` 把横向几何恢复为持久布局的基准宽度。不要混用容器像素和持久布局坐标，也不要在指针移动帧中重复转换已转换的结果。

一次缩放的 `dx/dy` 相对于**手势开始时**的几何计算，而不是上一帧。共享边界在手势开始时准备，帧更新仅复制改变的模块记录。撤销历史、旧版本迁移信息和模块实例不能在每一帧被深拷贝。

约束数值属于现有行为：横向安全尺寸 `64`，纵向安全尺寸 `40`，默认间距 `10`。短于安全尺寸的现有模块不会被强制扩大。竖向没有人为最大高度，横向受画布边界约束。碰撞计算中的浮点容差、共享边界的邻接判定及参与者顺序应通过几何回归验证后再改动。

## 3. 拖拽和缩放生命周期

### 模块拖拽

停靠栏的拖拽同时要求按下至少 `180 ms` 和移动至少 `6 px`。命中区域通过 `elementFromPoint()` 和 `data-drop-edge` 确定。松开后仅提交一次分割或新增行；拖拽结束产生的点击被抑制，避免又执行一次普通恢复。Escape、窗口失焦和指针取消会取消手势。

拖拽与缩放有各自的调度实现，不能将二者误认为共享一个控制器。当前拖拽的边缘滚动在移动事件的动画帧中执行；缩放能够在指针停留于边缘时持续调度。

### 模块缩放

`WorkspaceGrid` 接受主按键的指针按下，捕获指针，准备边界计算器，再创建一个 `ResizeSessionController`。浏览器模块收到 `companion-workspace-resize` 事件后临时隐藏原生网页，防止网页表面遮挡手势。

每帧的关键顺序如下：

1. 保留最新指针位置，一个控制器最多排队一个 `requestAnimationFrame`。
2. 需要时重新读取容器、画布和视口测量。
3. 使用手势起点、当前滚动量及边缘滚动增量计算目标布局。
4. 根据目标画布高度限制滚动；必要时重新计算几何，仍只绘制一次。
5. 更新改变的模块和分割线样式，再应用允许的滚动量。

边缘滚动区域最多 `80 px`，按视口高度缩小；现有速度范围为 `360–1200 px/s`，帧时间增量最多 `50 ms`。在遇到尺寸或滚动边界时不应无限调度无变化的帧。

指针松开先使用最新位置刷新最后一帧，再停止控制器、释放捕获、恢复滚动样式、通知网页模块并提交持久坐标。Escape、失焦、布局替换、指针取消、捕获丢失和卸载执行取消：恢复原可见布局，不提交中间结果。拖动期间禁止 React 布局状态和磁盘保存逐帧更新。

`WorkspaceGrid` 的原生监听在挂载时注册，并通过 refs 读取正在进行的手势和最新提交回调。不要仅为了消除 Hook 提示而将这些监听每次渲染重建，否则会改变手势取消时机。

## 4. 布局保存和恢复

当前布局的首选 key 是工作会话 ID；尚未创建工作会话时使用 `pending:` 前缀。新工作会话可回退到上一个会话或对话布局，再回退到 `@default-template`。

桌面版通过受信任窗口的 `workbench-layout` IPC 保存到用户目录中的 `workbench-layout.json`。主进程验证布局，并通过临时文件加重命名写入；网页调试环境使用 `localStorage` 的 `work-layout-` 前缀。公开源码不含用户的布局文件。

撤销历史最多保留十次，不含历史自身和旧迁移元数据的递归副本。已合法且没有重叠的 V3 布局必须准确恢复，不能以“整理”为由重新打包。V1/V2 仍可由主进程读取，并交给前端迁移；不要将旧输入直接当作完整 V3 数据。主进程在跨版本保存时保留一次旧文件备份，不自动执行旧任务。

存储的模块 ID、版本和 key 是兼容约定。改变这些字段前需考虑历史恢复，不能只验证新建空布局。

## 5. 会话与流式回复归属

`ConversationRuntimeStore` 是渲染器内存中的会话状态和排队器。草稿使用按会话区分的 `localStorage` key。完整聊天历史由后端数据库保存；该内存 store 不是磁盘数据库。

默认并发路径由 `ConversationSubmissionService` 执行：同一会话排队，不同会话可独立处理。提交携带角色、会话、模式、附件等快照，导航仅改变展示，不能把后台结果写入另一会话。`AppV3` 仍保留兼容的旧串行路径，本轮维护不删除或重新选择这条路径。

流式消费顺序中，用户保存事件替换临时 ID，助手开始事件建立真实回复归属，文字增量通过 `FirstSpeechGate` 展示，完成事件确认文本已保存。**文本完成后释放同会话排队，语音流仍可继续消费和缓存。** 不要把文本排队释放改为等待完整长语音，也不要在结束文本时截断音频流。

`VoicePresentationService` 核对回复、语音会话和片段序号。重复片段被忽略，序号缺失停止播放；后台会话仍消费事件以保存语音，但不占用当前声音输出。切换会话或开始下一条可听回复会分离旧播放展示，停止任务则使用对应会话的取消控制器。

`FirstSpeechGate` 在第一段真实播放或最多两秒等待后释放文字，随后逐步展示。音频队列支持原生 PCM 与浏览器音频回退，并将连续片段加入同一个回复输出。不要在格式或注释整理中改变缓冲时间、片段顺序和完成通知。

`api.ts` 的 SSE 读取器按完整事件边界解析，结束时取消 reader 并释放锁。主进程的 renderer registry 单独记录受信任窗口上下文；嵌入网页不会成为授权渲染器。

## 6. 验证范围和限制

| 测试 | 已验证内容 | 不能据此宣称 |
| --- | --- | --- |
| `tests/ui/v87-layout-unit.cjs` | 共享横纵边界、固定障碍、最小尺寸、8 模块多轮操作、序列化恢复 | 真实界面帧率、指针手势和声音播放 |
| `tests/ui/v89-layout-unit.cjs` | 四边缩放、T 形连接、准确恢复、响应式坐标、连续计算不复制历史 | renderer FPS 或人工界面验收 |
| `tests/ui/v85-submission-unit.cjs` | 同会话消息排队、跨会话独立、后台语音不播放且可缓存 | 外部模型或 Windows 音频设备可用 |
| `tests/ui/clean-character-ownership.cjs` | 角色和并发请求归属 | 完整后端持久化 |
| `tests/ui/clean-character-studio.cjs` | 隔离 Electron、真实 IPC、角色文件输入、重启和本地模拟模型 | 真实模型质量、完整工作台手势验收 |

纯几何性能结果仅描述 CPU 算法，不代表 DOM 绘制性能。上述单测使用本地模拟数据，不需要付费 API。

工作台界面验收还应在隔离用户目录执行真实拖拽、共享分割线缩放、边缘自动滚动、取消和重启恢复。应明确记录哪些是自动化检查、哪些需要人工观察；不能用编译成功代替这些验收，也不能把测试记录写入正式聊天或个人版数据。
