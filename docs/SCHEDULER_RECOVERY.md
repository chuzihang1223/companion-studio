# 中断、恢复与去重

正常完全退出把自己的活动调度运行标为 INTERRUPTED；用户点取消为 CANCELLED。
进程意外终止后，原 Runtime / Workflow / Checkpoint 先恢复账本，再由调度观察器对齐。
原运行不存在、提交后协程未启动或副作用未知时进入 NEEDS_REVIEW，不能重新 start。

同一档案有 OS 文件锁，持有者存在时第二后端在任何恢复写入前拒绝启动。
SQLite Lease 绑定随机 token 与 PID 创建身份；仅时钟前跳、租约到期不能抢占仍存活的进程。
进程消失也要查原运行状态；租约不能代替执行事实。

历史 → 恢复预览使用原 WorkflowCheckpointAdapter 和 StateReconciler。
用户明确确认后，重新验证版本、来源、权限、revision 和预览，受控领取同一个运行再续接。
已核验的节点可以保留；未知外部输入、发送、脚本、模型请求与 MCP 副作用不自动重放。
本次同意不是永久或未来动态参数授权，恢复不增加原请求或工具预算。

数据库忙碌时退出仍停止内存中明确属于本实例的协程；持久化失败记录固定错误代码。
下一次恢复保守分类，不能因为退出时没能写账本而宣称任务已经成功。
没有跨外部系统事务，也没有分布式 Exactly Once。
