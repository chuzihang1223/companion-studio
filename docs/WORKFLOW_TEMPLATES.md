# 三个 MIT 工作流模板

模板由本项目原创，遵循根目录 MIT License。打开模板只创建可编辑草稿。
不会隐式导入 Skill、选择项目、启动 MCP、授予写入权限或发送模型请求。
所需依赖未准备时，校验给出对应节点错误，不伪装为可执行。

## 项目检查报告

手动开始 → 输入项目内相对文件路径 → 原 workspace.read → 已启用 project-review Skill
→ 原 LLMService 整理建议 → Markdown 输出。

先在 MCP & Skills 管理中导入并启用内置 project-review 示例，在工作模式选择一个测试项目，
配置自己可用的模型。打开模板时自动填入已经启用的同名 Skill ID 和内容摘要；已有模板可在右侧
重新选择 Skill。输入示例：

```json
{"path":"README.md"}
```

输出是模型根据实际读取内容形成的 Markdown，不代表已运行项目测试，也不自动写入文件。

## 代码测试与报告

手动开始 → 输入 .py 测试路径 → 先读取脚本 → code.run（逐次授权，默认所选项目的隔离副本）
→ 退出码条件 → 成功 / 失败 / 执行错误分支 → Merge → Markdown 报告。

```json
{"path":"check_fixture.py"}
```

需当前机器有可用 Python。实际副本执行使用原 15 秒超时 / 16 KB 输出约束；不是任意 Shell 节点。
测试脚本拥有当前账号权限，先审阅脚本。这个模板不调用模型。执行器失败走显式错误分支；
权限拒绝停止整个运行，不能经错误分支继续绕过。

## MCP 数据整理

手动开始 → 主题输入 → 已手动连接、启用的 MCP echo → 字段选择 → 模型总结 → 文本输出。

```json
{"topic":"用于本机测试的合成主题"}
```

可使用应用随附的受控 MCP Demo，无需第三方账户。连接方式见 [MCP 配置](MCP_CONFIGURATION.md)。
先连接 Demo、显式启用 echo 并选择只读风险，再打开模板；或者手动选择右侧已发现的工具及其参数。
替换工具时必须适配当前 input_schema，并重新发布。协议响应会保留 untrusted 标记和
`goal_verified=false`，模型不能把 echo 结果说成真实研究验证完成。

## 复用边界

可查看、复制草稿、编辑、发布本地版本、导入/导出 JSON、归档和删除自己的草稿。
每个工具节点有独立工作会话；隔离草稿不会自动当成下一节点的实体项目文件执行。
跨节点内容通过显式变量传递，实际写文件仍需原权限。模板不扫描整个磁盘、不自动执行项目的未知脚本。
