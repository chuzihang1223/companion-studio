# 知识与记忆安全边界

## 权限链

主窗口固定 IPC → 主进程目录选择/必要原生确认 → 受控 API → 会话/角色与 Collection grant
→ 根目录身份/路径/句柄/文件哈希核验。检索内容来自用户授权文件，不是可信系统指令。
glob、模型输出、导入 Skill、Workflow 图、MCP 返回都不能扩大目录权限。

本地检索与传输给模型分别授权。模型目标指纹由 provider/base_url/model 组成，不包含密钥。
主进程显示当前四个模型职责的地址和名称，后台核对确认前后的指纹；热切换失效旧授权。
Embedding 有独立 endpoint/模型/修订/维度配置和传输确认，不复用聊天密钥。
授权只限制本程序发送的内容；不能控制用户选择的外部服务如何存储数据。

## 防护

- 不默认扫描磁盘；根目录不能是盘根、应用数据/密钥目录；不跟随 symlink/junction/reparse point。
- 所有具体文件读取先验证词法范围，再检查打开句柄路径和读前/读后状态；源文件变化使证据失效。
- 不执行文档脚本、宏、XML 实体或 OCR；解析子进程有截止时间、输出和内存边界。
- FTS/SQL 参数化，查询语法来自限定词法器；向量不使用 pickle，维度/版本严格隔离。
- Chat、工具、Workflow 与桌面搜索共享最多四个并发检索名额；突发超额立即返回 429 / `KNOWLEDGE_QUERY_BUSY`，不无限排队，异常也会释放名额。此限制是并发背压，不是按分钟的用户配额。
- 模型引用只能指向实际提供的 chunk ID；资料中的指令不能提升工具权限。
- Agent 在知识结果之后阻止无关 MCP/浏览器传输；Workflow 根据真实祖先保留来源约束，转换不能洗掉约束。
- Trace 仅允许固定事件、UUID、计数和耗时，不保存查询、摘录、模型请求、文件绝对路径或原始错误。
- Checkpoint 保存身份/摘要，恢复重新核对；未知状态、来源过期、撤销授权不自动重试或复用。
- 原角色记忆和新记忆入口都检查常见秘密模式，启停/删除/到期即时影响后续查询。

## 实际限制

SQLite 索引、消息和手动记忆是当前用户档案中的明文数据；不是磁盘加密或操作系统沙箱。
应用不能防御同一 Windows 账户下其他恶意进程，也不能撤回已经发往已授权服务的数据。
哈希核验与外部模型生成之间仍可能发生源文件变化；引用再次打开时会重新检查。
模型可能误解合法证据，系统只证明来源身份与权限，没有证明每句自然语言结论。
公开导出明确排除档案、源文档、向量库、测试报告、模型权重和私人历史目录。
